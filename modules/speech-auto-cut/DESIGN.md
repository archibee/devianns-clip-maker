# 음성 기반 자동 컷 편집 모듈 설계

분석 기준일: 2026-11-14. 상태: **구현 가능성 조사 및 독립 실행 추론 시험 완료 / 제품 기능은 아직 미구현**.

이번 작업은 이 문서만 추가한다. 기존 `src/`, 의존성/잠금 파일, Vite 설정, 배포 명령 및 다른 문서는 변경하지 않는다. 아래 폴더/파일과 UI는 앞으로 구현할 설계이며 이미 존재하는 기능을 의미하지 않는다.

## 1. 결론과 목표

Silero VAD의 공식 ONNX 모델과 ONNX Runtime Web을 사용하면 GitHub Pages에 정적 파일로 배포할 수 있는 로컬 음성 분석 기능을 만들 수 있다. 원본 영상·소리를 외부 API로 전송하지 않고 브라우저에서 처리한다. 여기서 사용하는 API는 브라우저 안의 추론 라이브러리 API이며 원격 음성 분석 서비스가 아니다.

목표 흐름은 다음과 같다.

```text
원본 영상 또는 기존 프로젝트 JSON + 원본 파일
  → 현재 편집 구간의 오디오를 블록 단위로 읽기
  → 16kHz 음성 확률 추론
  → 짧은 말·약한 말 우선 보존 + 앞뒤 여백
  → 유지/삭제 후보와 편집 후 재생 결과 미리보기
  → 사용자가 후보를 수정하고 [확정]
  → 남길 원본 구간을 참조하는 영상/소리 블록을 순서대로 연결
  → 기존 편집기가 읽을 수 있는 프로젝트 JSON 출력
  → 기존 편집기에서 열고 자막 작업·최종 영상 출력
```

자동 자막 생성·음성 인식·화자 분리·내용의 중요도 판단은 범위에 넣지 않는다. 영상과 원본 소리는 같은 원본 구간을 참조하며 함께 자른다. 확정 전에는 원본 프로젝트를 변경하지 않는다.

## 2. 구현 가능성을 확인한 근거

### 공식 자료

- 공식 Silero 저장소와 해당 모델 배포 경로의 LICENSE는 MIT다. 선택한 공식 배포물은 저작권 및 허가 고지를 보존하는 조건으로 상업적 사용·수정·재배포가 가능한 경로다. 출처가 다른 과거 모델에 같은 판단을 소급하지 않는다. [Silero LICENSE](https://github.com/snakers4/silero-vad/blob/066409f3d9db45a30d21dfcbf9147826ffdd7052/LICENSE)
- ONNX Runtime의 공식 LICENSE도 MIT다. 실제 사용 버전의 라이선스와 포함된 제3자 고지를 배포물에 함께 보존한다. 모델과 런타임의 고지는 따로 관리한다. [ONNX Runtime LICENSE](https://github.com/microsoft/onnxruntime/blob/main/LICENSE)
- ONNX Runtime Web은 JS·WASM·ONNX 파일을 정적 호스트에서 제공할 수 있다. `numThreads=1`이면 다중 스레드를 사용하지 않으므로 이 경로에서 SharedArrayBuffer·COOP/COEP가 필수 조건이 아니다. [정적 배포](https://onnxruntime.ai/docs/tutorials/web/deploy.html), [스레드 설정](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html)
- Silero 관리자가 안내한 브라우저 구현 사례와 파일 오디오용 `NonRealTimeVAD` API도 있다. 다만 이번 설계는 래퍼의 마이크 입력·전체 PCM 보관 방식을 그대로 도입하지 않고 파일 분석용 Worker 어댑터를 둔다. [공식 토론](https://github.com/snakers4/silero-vad/discussions/175), [브라우저 VAD API](https://docs.vad.ricky0123.com/user-guide/api/)

## 3. 사용자가 제공한 설명에서 보완할 점

1. VAD는 음성이 반드시 보존된다는 보증을 제공하지 않는다. 낮은 임계값·여백은 누락 위험을 줄이는 전략이며, 속삭임·배경 음악·매우 짧은 발화·채널 이상에서 오판이 남는다.
2. `minSpeechDuration=100ms`도 그보다 짧은 말이나 모델이 약하게 감지한 말을 버릴 수 있다. 초기 기본값은 짧은 검출 구간을 자동 탈락시키지 않는 쪽으로 정한다.
3. 최소 음성 길이·음성 종료 대기·앞뒤 여백·가까운 구간 병합 등은 모델 자체의 단순 인자가 아니라 후처리 정책이다. 명시적으로 구현해야 한다. 래퍼마다 옵션 이름과 단위도 다르다.
4. 모델 크기 약 2.33MB가 기능 전체의 다운로드 크기는 아니다. 시험한 런타임 패키지의 WASM 변형은 약 15~30MB 규모의 파일도 포함한다. 실제 빌드에서는 사용하는 백엔드/변형만 선별하고 크기를 측정한다.
5. 오래된 제3자 문서의 비상업 라이선스 표기가 생긴 원인은 이번 조사에서 확인하지 않았다. 임의 미러 파일을 혼용하지 않고 공식 revision·모델 해시·동일 revision의 LICENSE를 함께 고정한다.

## 4. 기존 코드 무수정 조건과 연결 방식

현재 편집기에는 외부 모듈을 등록하거나 프로젝트 전체를 하나의 undo 명령으로 교체하는 플러그인 API가 없다. **새 폴더를 만드는 것만으로 기존 화면에 자동 컷 버튼이 나타나거나 현재 편집 상태를 직접 수정하지는 못한다.** 기존 코드 무수정 조건에서는 다음 독립 실행 방식을 우선한다.

### 초기 배포: 독립 도구 + 프로젝트 JSON 왕복

- 새 모듈에 자체 HTML 진입점·UI·빌드 설정을 둔다.
- 사용자는 이 도구에 영상을 직접 넣거나 기존 프로젝트 JSON과 원본 파일을 연다.
- 분석·후보 수정·미리보기·확정은 도구 내부 상태에서 처리한다.
- 결과를 현행 `schemaVersion:1` 프로젝트 JSON으로 저장한다.
- 기존 편집기에서 결과 JSON을 열고 원본 파일을 다시 연결한다. 기존 미리보기·출력·자막 기능을 그대로 사용한다.
- 확정 전/후 프로젝트를 모듈 안에서 되돌릴 수 있게 한다. 기존 편집기에서 JSON을 여는 동작은 현재 구조상 이력을 새로 시작하므로 기존 편집기의 단일 undo로 원상복구된다고 표시하지 않는다. 원본 JSON도 보존한다.

### 선택적인 향후 통합

독립 모듈은 `analyze()`, `buildProposal()`, `buildResultProject()`, `cancel()`, `dispose()` 형태의 공개 경계를 제공한다. 나중에 기존 편집기 안에서 호출하려면 버튼과 프로젝트 snapshot 읽기/한 번에 적용하는 host adapter 연결이 별도로 필요하다. 이는 기존 파일의 최소 연결 변경을 허용하는 후속 작업으로 구분하며 이번 문서만으로 승인되거나 구현된 것으로 보지 않는다. 전역 함수 덮어쓰기·DOM 탐색·기존 reducer 가로채기로 연결하지 않는다.

## 5. 새 모듈의 폴더와 책임

다음은 앞으로 만들 파일이다. 현재는 `DESIGN.md`만 추가한다.

```text
modules/speech-auto-cut/

  public/vendor/                      선택 모델·ORT 자산·라이선스·manifest
  src/
    index.ts                          공개 API, 기존 앱에 부작용 없음
    contracts.ts                      요청·진행률·구간·제안·오류 타입
    audio/file-pcm-reader.ts           원본별 오디오 블록 디코딩

    detection/keep-policy.ts           여백·병합·보호 구간·수동 수정

    editing/project-adapter.ts         기존 Clip/parts → 결과 Project
    preview/preview-adapter.ts         원본/후보 미리보기 연결
```

`Project`, `mediaLayout()`, `parseProject()` 등 기존 데이터 계약과 순수 해석 함수는 adapter 경계에서 읽기 전용으로 재사용할 수 있다. 미리보기 역시 기존 `PlaybackService`와 별도의 `MediaRegistry` 인스턴스를 사용하도록 새 adapter에서 감싼다. 원래 편집기의 인스턴스를 공유하거나 기존 파일을 복사해 변형하지 않는다. 기존 Worker·번들 폰트가 독립 빌드에서도 해석되도록 모듈 설정/스테이징에서 포함한다.

새 모듈은 기본 편집기 시작 시 로드되지 않는다. 사용자가 독립 도구를 열고 분석을 시작할 때 모델/런타임을 준비한다. 음성 분석 실패가 기본 편집기 실행을 막지 않는다.

## 6. 오디오와 추론 처리

### 입력과 시간 기준

- 분석 대상은 현재 프로젝트에서 실제 사용하는 영상 구간이다. `parts`가 있는 합친 블록도 `mediaLayout()` 기준으로 원본/원본 in-out/프로젝트 시작 시간을 풀어 해석한다.
- 각 원본을 독립적으로 열고 기존과 같은 mono/stereo 및 디코딩 지원 조건을 적용한다. 전체 원본의 `arrayBuffer()`나 전체 길이 PCM을 기본 경로로 사용하지 않는다.
- 원본 오디오 PTS와 영상의 기준 origin 차이를 보존한다. `원본 시각 = videoOrigin + clip.inUs + 구간 내 경과 시간`을 기준으로 정렬하며 샘플 배열의 0번을 무조건 영상 0초로 취급하지 않는다.
- 원본 샘플 번호로 연속 리샘플링 위상을 유지한다. 44.1/48kHz 등의 신호를 저역통과 필터가 있는 16kHz 변환기로 처리하고 매 블록을 독립 반올림해 누적 드리프트를 만들지 않는다.
- stereo는 단순 `(L+R)/2`만 사용하지 않는다. 역상 음성이 상쇄될 수 있으므로 초기 안전 모드는 채널별 독립 상태로 추론하고 프레임별 음성 판정을 OR/최대 확률로 합친다.

### 모델 어댑터

시험한 공식 모델을 기준으로 입력 프레임은 512개 float32 샘플(32ms)이고 이전 문맥 64개를 앞에 붙인다. 첫 문맥은 0이며 상태는 `[2,1,128]` float32다. `sr`은 int64 스칼라 16000이다. 다음 프레임에는 `stateN`과 마지막 문맥을 전달한다. 새 원본/불연속 구간/새 작업에서는 상태와 문맥을 초기화하고, 같은 연속 스트림의 매 프레임마다 초기화하지 않는다. 마지막 불완전 프레임은 패딩하되 유효 끝 시각은 원래 길이로 제한한다.

이 규약은 선택 모델에 대한 것으로 버전마다 재확인한다. 문맥 없이 512개만 넣어도 예외 없이 낮은 확률이 나올 수 있으므로 음성/무음 대조 fixture를 출시 전 필수 검사로 둔다. [공식 wrapper](https://github.com/snakers4/silero-vad/blob/066409f3d9db45a30d21dfcbf9147826ffdd7052/src/silero_vad/utils_vad.py), [관련 이슈](https://github.com/snakers4/silero-vad/issues/771)

### Worker와 자원

- `executionProviders:['wasm']`, `ort.env.wasm.numThreads=1`, 자체 Worker 내부에서는 `proxy=false`를 기본으로 한다. WebGPU는 기본 조건이 아니다.
- PCM 입력 큐는 수 초 단위로 제한하고 전송 완료 후 다음 블록을 보내 backpressure를 둔다. AudioSample/AudioData는 읽은 뒤 즉시 해제한다.
- 모델은 모듈을 사용하는 동안 재사용하되 세션 상태는 작업/채널별로 분리한다. 취소 시 디코더·PCM 큐·추론 루프를 중단하고 미완료 제안을 버린다. 필요하면 Worker를 종료하고 다음 분석 때 다시 만든다.
- `jobId`와 입력 프로젝트 식별값/옵션 fingerprint로 오래된 응답을 무시한다. 분석 후 입력이나 옵션이 바뀌면 확정하지 않고 다시 분석한다.
- 저장 가능한 분석 캐시에는 시간 구간·옵션·모델 해시·원본 식별 정보만 둔다. 원본 PCM/파일을 자동 업로드하거나 프로젝트 JSON에 넣지 않는다. 확률 trace도 크기 상한을 둔다.

## 7. 음성 보존 우선 후처리

초기 제안값이며 정확도가 검증된 최종 수치는 아니다.

| 설정 | 초기 값/정책 | 이유 |
| --- | --- | --- |
| 음성 시작 확률 | 0.40 | 낮은 목소리 보존을 우선 |
| 음성 종료 확률 | 0.25 | 시작/종료를 분리해 흔들림 방지 |
| 종료 판단 대기 | 비음성 약 400ms | 말 사이 짧은 틈을 바로 잘라내지 않음 |
| 앞/뒤 보존 여백 | 각각 300ms | 첫 음소·말끝 보존 |
| 최소 음성 길이 필터 | 기본 비활성화 | 짧은 감탄사/응답을 길이만으로 버리지 않음 |
| 실제 삭제 최소 길이 | 여백 확장·병합 후 700ms 이상의 비음성 후보 | 사소한 틈 제거보다 긴 공백 정리에 집중 |
| 가까운 유지 구간 | 겹치거나 맞닿으면 병합 | 같은 원본 시간을 중복 사용하지 않음 |
| 음성 없는 분석 결과 | 기본 전체 보존, 자동 전체 삭제 금지 | 무음/오검출/잘못된 입력을 구분할 수 없음 |

음성 확률이 임계값을 넘은 짧은 조각도 먼저 보존 후보로 만든다. 종료 대기와 padding을 중복 적용해 지나치게 넓히지 않도록 기준 시각을 정의한다. 여백은 이미 편집된 원본 in/out 안으로 제한하며 기존 컷 밖의 내용을 임의 복원하지 않는다.

오디오가 없거나 디코딩 불가·채널 이상·모델 오류·분석 중 누락 파일이 있는 경우를 비음성으로 간주해 삭제하지 않는다. 오디오 없는 블록은 기본 보존/수동 검토 대상이다. 분석 실패 구간은 보존하거나 작업을 실패 처리하고 원본 프로젝트는 유지한다. 음악/환경음은 사용자에게 별도 보존 구간으로 표시할 수 있게 한다.

## 8. 컷 계획과 기존 프로젝트 호환

모든 시간은 정수 마이크로초, 구간은 `[startUs,endUs)`로 관리한다. 음성 후보는 바깥쪽으로 프레임 경계를 잡아 안전하게 늘릴 수 있으며, 30/45/60fps에서 `floor/ceil`을 경계마다 계산하고 프레임 길이를 누적해 더하지 않는다. 구간 병합 후 원래 편집 범위로 다시 제한한다.

정렬·병합된 유지 구간을 `[a,b)`라고 하고, 기존 원본 해석 결과를 `[row.startUs,row.endUs)`라고 할 때 교집합마다 다음 블록을 만든다.

```text
sourceIn  = row.clip.inUs + intersectionStart - row.startUs
sourceOut = row.clip.inUs + intersectionEnd   - row.startUs
newStart  = 지금까지 남긴 영상 구간 길이의 합
```

- 원본 `assetId`, Crop/Move/Resize 등 `transform`을 복제하고 새로운 블록 ID를 부여한다.
- 결과 영상 블록은 0초부터 빈틈 없이 이어 붙인다. 원본 비디오/오디오 참조는 동일하므로 싱크를 함께 유지한다.
- 합친 블록은 실제 구성 원본별 조각으로 풀어 결과를 만든다. 영상 파일을 분석 단계에서 다시 인코딩하지 않는다.
- 결과의 `assets`, 프로젝트 이름/화면 비율/FPS 및 현행 스키마를 유지한다. 모델·추론 상태·File/Blob은 프로젝트 JSON에 추가하지 않는다.
- 제안에는 이전 시간과 새 시간을 연결하는 `timeMap`을 별도로 둔다. 유지 길이의 합과 결과 길이가 일치하고, 겹침·음수·원본 범위 초과가 없어야 한다. 출력 전 기존 `parseProject()`로 호환성을 확인한다.

### 이미 자막이 있는 프로젝트

현재 자막은 프로젝트 시간에 고정되므로 영상만 당기면 기존 자막이 어긋난다. 이를 자동으로 방치하지 않는다. **초기 모듈은 자막 작업 전 사용을 기본으로 하고, 기존 자막이 있으면 그대로 덮어쓰는 확정을 막는다.** 사용자가 명시적으로 「자막을 제외한 새 편집본 만들기」를 선택할 경우에만 원본은 그대로 두고 `subtitles:[]`인 새 결과를 만든다. 자막을 조용히 삭제하거나 옛 시간을 그대로 옮기지 않는다.

자막 보존 자동 재매핑은 후속 범위다. 구현한다면 `timeMap`과 유지 구간의 교집합을 기준으로 이동/분할하고, 삭제 구간의 자막 처리·겹침·글자 반복 정책까지 검증한 후 활성화한다.

## 9. 독립 도구 UI와 사용자 흐름

1. **가져오기**: 영상 직접 입력 또는 프로젝트 JSON + 원본 재연결. 예상 길이와 분석 범위를 표시한다.
2. **음성 분석**: 진행률·취소, 보존 우선 옵션을 제공한다. 이 단계에서는 편집 결과를 적용하지 않는다.
3. **후보 확인**: 유지/삭제 예정 구간을 색과 텍스트로 구분한다. 원본 재생과 연결된 결과 재생을 모두 제공하며 삭제 후보를 클릭해 해당 원본을 들어볼 수 있다.
4. **수정**: 후보마다 「보존」 전환과 경계/여백 수정이 가능하다. 낮은 확률 구간·오디오 없는 블록은 검토 대상으로 표시한다. 최종 유지 구간이 없으면 확정은 비활성화한다.
5. **확정**: 삭제될 총 길이·남길 블록 수·결과 길이를 요약하고, 사용자의 확정 한 번으로 새 프로젝트 snapshot을 만든다. 모듈 내부 되돌리기로 원본 snapshot에 돌아갈 수 있다.
6. **결과 열기**: JSON 다운로드 후 기존 편집기에서 열고 원본을 재연결한다. 자막 작업과 최종 인코딩은 기존 편집기를 사용한다.

자동 분석 결과가 늘 옳다고 표현하지 않는다. 「자동 무음 삭제」보다는 「음성 기준 컷 제안」이라는 설명을 사용한다. 마이크 권한·서버 업로드·회원가입은 요구하지 않는다.

## 10. 정적 배포와 라이선스 파일

- 독립 모듈은 자신의 `vite.config.ts`와 잠금 파일로 빌드한다. 기존 루트 설정은 수정하지 않는다.
- 향후 배포 순서는 기존 편집기 빌드 → 새 모듈 빌드 → 새 모듈 스테이징 스크립트로 `dist/tools/speech-auto-cut/`에 복사 → 기존 `gh-pages -d dist` 배포다. 기존 빌드가 `dist`를 지우므로 모듈 복사는 마지막에 한다. 이 순서는 계획이며 아직 실행 가능한 모듈 빌드 명령이 구현된 것은 아니다.
- `base:'./'`와 `import.meta.url` 기준으로 Worker·모델·WASM 경로를 해석한다. `/models/...` 같은 도메인 루트 절대 경로, CDN 자동 폴백, 프록시 API를 기본값으로 넣지 않는다.
- 모델은 공식 revision과 위 SHA-256을 고정한다. ORT JS와 WASM은 같은 npm 버전으로 고정하고, 선택한 파일 목록/버전/해시/출처를 manifest에 기록한다. 현재 사용하지 않는 WebGPU·다른 WASM 변형을 모두 배포하지 않는다.
- 모듈 자체의 `public/vendor/licenses/` 등에 Silero MIT, ONNX Runtime MIT 및 해당 배포물의 제3자 고지를 포함한다. 향후 래퍼를 도입하면 그 래퍼의 ISC/MIT 등 별도 고지도 확인한다. 현재 설계는 추가 래퍼 설치를 전제로 하지 않는다.
- 배포 후 초기 네트워크는 사이트 자체의 정적 자산 다운로드만 발생한다. 원본 영상·추출 오디오·자막·분석 결과는 업로드하지 않는다.
- `application/wasm` MIME, 404/경로 오류, 모델/런타임 버전 불일치, SIMD 미지원, 초기화 시간 제한과 재시도 안내를 검사한다. 이 경로는 현재 편집기와 같은 데스크톱 Chrome/Edge를 우선 대상으로 한다.

## 11. 향후 구현 순서와 완료 기준

아래는 앞으로 수행할 항목이며 이번 조사로 완료 표시하지 않는다.

- [ ] 모듈 전용 의존성/잠금 파일·진입점·라이선스/모델 manifest를 추가하고 정적 하위 경로에서 초기화한다.
- [ ] 파일 오디오를 전체 적재 없이 읽고 채널별 16kHz로 변환한다. 원본 PTS·44.1/48kHz·역상 stereo·오디오 없는 구간을 검사한다.
- [ ] 검증된 tensor/context/state 규약으로 Worker 추론·진행률·취소·오류 처리를 구현한다.
- [ ] 한국어 짧은 말·작은 목소리·속삭임·말끝·음악/환경음 fixture로 누락을 평가하고 보존 우선 기본값을 조정한다. 영어 샘플 시험만으로 한국어 정확도를 완료 처리하지 않는다.
- [ ] 후보 후처리·수동 보존/경계 조절·원본/편집 결과 미리보기를 구현한다.
- [ ] 합친 영상·트림·다른 원본·기존 변환·빈 구간을 포함한 cut-plan과 프로젝트 JSON 출력의 시간 매핑을 검사한다.
- [ ] 기존 자막이 있는 경우의 확정 제한/명시적 새 편집본 흐름과 모듈 내 되돌리기·원본 보존을 구현한다.
- [ ] 기존 편집기에서 결과 JSON을 읽고 1080p/720p/480p, 30/45/60fps 출력의 영상/소리 동기·컷 경계·길이를 확인한다.
- [ ] GitHub Pages와 같은 비격리 정적 환경의 루트/저장소 하위 경로에서 모델·WASM·Worker·폰트 로딩과 외부 업로드 없음을 확인한다.
- [ ] 실제 장시간 파일의 메모리·분석 취소·모델 재사용·재시도·실패 후 기존 편집기 정상 실행을 검증한다.

출시 판단은 모델의 실행 성공만으로 하지 않는다. 특히 음성 누락률과 짧은 발화 보존은 실제 검수 자료로 판단하며, 완전한 음성 무손실 자동 컷이라는 보장은 하지 않는다.
