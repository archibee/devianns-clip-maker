# 최종 내보내기 용량 업그레이드 v2

- [v] F201. 메모리 다운로드의 앱 자체 256MiB 상한을 제거하고 현재 설치된 Mediabunny BufferTarget의 코드상 최대 ArrayBuffer 크기인 2^32바이트(4096MiB)까지 허용한다. 이는 모든 브라우저/기기의 성공 가능 용량을 보장하는 수치가 아니며 실제 메모리 부족으로 더 일찍 실패할 수 있다.
- [v] F202. 파일 직접 저장은 기존 스트리밍 경로를 유지하고 앱 차원의 고정 MB 상한을 두지 않는다. 예상 출력 바이트가 표현 불가능한 값이면 거부하고 실제 저장 공간/파일 시스템/브라우저 오류와 취소는 기존 실패 처리로 안내한다. 메모리 경로의 상한 때문에 직접 저장까지 막지 않는다.
- [v] F203. 최종 편집 타임라인과 선택 해상도/FPS/오디오 비트레이트로 계산한 예상 출력 용량을 허용 여부 기준으로 사용한다. 클립 총 시간·영상 길이·원본 파일 크기로 별도 내보내기 제한을 추가하지 않는다. 비어 있는 출력·잘못된 프로젝트·코덱 미지원·원본 누락 등 필수 검사는 유지한다.
- [v] F204. UI·내보내기 서비스·Worker가 같은 용량 판단과 상한 안내를 사용한다. 메모리 경로는 실제 출력이 상한을 넘는 경우도 거부하고 직접 저장을 안내한다. Worker의 버퍼 할당 오류와 완료 후 Blob 준비 실패는 완료로 표시하지 않고 오류로 안내한다. 고용량 출력을 직접 저장으로 처리할 수 있다는 안내를 제공한다.
- [v] F205. 사용자 요청에 따라 타입 검사·빌드·테스트·브라우저/실제 대용량 출력 검증은 실행하지 않는다. 코드에 적용한 항목만 체크하고 실제 성공 가능한 파일 크기를 실측했다고 주장하지 않는다.

기준은 현재 설치된 `node_modules/mediabunny/dist/modules/src/target.js`의 `ARRAY_BUFFER_MAX_SIZE = 2 ** 32` 및 BufferTarget의 크기 확장 검사다. 직접 저장은 `StreamTarget`에 1MiB 청크로 쓰는 기존 경로다. 장시간 출력은 처리 시간과 실제 자원이 필요하며, 이번 변경은 시간 제한으로 사전 차단하지 않는다는 의미다.

구현 완료 기준으로 체크했다. 타입 검사·빌드·테스트·브라우저/대용량 출력 실행은 사용자 요청에 따라 생략했다.
