## 문제 상황과 수정 전 코드

### 자막 선택·조작 경로 누락

수정 전 [Timeline.tsx](../../src/editor/Timeline.tsx)의 자막 레인은 표시용 span만 생성했다. 클릭·포커스·드래그·트림 처리와 선택 속성이 없었다.

```tsx
<span style={{ left: ..., width: ... }} title={c.text}>
  T {c.text}
</span>
```

[Inspector.tsx](../../src/editor/Inspector.tsx)는 cueId를 로컬 상태로만 보관했고 [App.tsx](../../src/app/App.tsx)는 영상 선택만 관리했다. 타임라인 선택을 기존 속성 패널이나 공통 삭제 명령에 연결할 경로가 없었다. 실제 브라우저에서 자막 요소의 role/tabindex/aria-pressed가 모두 없음을 확인했다. [수정 전 기록](../validation/v2-before.json)

### 분할·삭제·단축키의 대상 제한

[commands.ts](../../src/project/commands.ts)의 기존 split은 clips만 변경했다. 영상 경계에서는 즉시 반환해 그 위치를 가로지르는 자막도 분할되지 않았다.

```ts
const item = resolve(project, timeUs);
if (!item || item.sourceUs <= item.clip.inUs || item.sourceUs >= item.clip.outUs) return project;
// clips만 변경, subtitles는 유지
```

App의 공통 삭제는 영상 ID에 대해서만 delete를 보냈고, 자막 삭제는 Inspector 내부 버튼에만 연결되어 있었다. [useShortcuts.ts](../../src/editor/useShortcuts.ts)는 S/Delete 등을 처리했지만 숫자 1·2는 처리하지 않았다.

### 오디오 상태에 묶인 재생과 첫 프레임 대기 누락

[PlaybackService](../../src/playback/service.ts)의 기존 재생은 무음 여부와 관계없이 다음 경로를 실행했다.

```ts
this.audio ??= new AudioContext({ sampleRate: AUDIO_RATE });
await this.audio.resume();
// 모든 영상에 AudioContext.currentTime만 사용
```

수정 전 관찰을 구분한다.

- 정상적인 2초 합성 영상에서는 버튼 재생과 실제 프레임 진행이 가능했다. 사용자의 모든 원본·기기에서 같은 원인을 확인했다고 주장하지 않는다.
- 브라우저에서 AudioContext 생성 실패를 주입하자 무음 영상도 0초에서 재생하지 못했다. 소리가 없는 영상까지 오디오 장치에 의존했다.
- 실제 AudioContext를 resume 후 suspend시키는 조건에서는 시간 0초·버튼 ‘일시 정지’·오류 없음 상태가 재현됐다. 실행 상태와 시계 중단을 확인하지 않았다.
- resume이 끝나지 않을 때 시작 대기에 제한 시간이 없었다. 오래된 시작 요청의 catch도 이후 재생을 정지시킬 수 있었다.
- Worker의 첫 프레임 확인 전에 재생 시계를 시작했다. 초기 폰트·디코딩이 늦으면 화면이 비어 있는데 시간만 진행할 수 있었다.

오디오 조건과 수정 전 상태는 [v2-playback-before.json](../validation/v2-playback-before.json)에 보관한다. 이는 실제 브라우저의 제어된 재현 조건이며 물리적 장치 고장을 측정한 결과는 아니다.

## 반영된 개선

### 공유 선택과 기존 UI 연결

App에서 영상 선택·자막 선택·속성 탭을 관리하며 선택 종류를 구분한다. 타임라인 자막 클릭이나 Enter 선택 시 기존 자막 속성 탭이 열리고 내용·시간·스타일을 수정할 수 있다. 속성 목록과 타임라인의 선택도 일치한다. 클릭만으로 시간을 변경하지 않으며 대상 삭제 시 선택을 정리한다.

기존 삭제 버튼과 Delete/Backspace/숫자 2는 선택 자막 또는 영상을 삭제한다. 새 패널·도구막대는 추가하지 않았다.

### 자막 이동·길이 조절·붙여넣기

새 [SubtitleBlock.tsx](../../src/editor/SubtitleBlock.tsx)가 포인터 캡처·선택·드래그 초안·양끝 핸들을 담당한다. [subtitles.ts](../../src/project/subtitles.ts)는 시간 후보·스냅·유효성 검사를 담당한다.

- 본문 드래그는 길이·내용·스타일을 유지하고 시작/끝을 함께 이동한다.
- 양끝 핸들 또는 기존 속성 패널의 초 입력으로 길이를 변경한다.
- 인접 자막 시작/끝 및 영상 범위 경계에 6px 이내로 접근하면 스냅한다. 붙어 있는 반개구간 `[start, end)`은 겹침으로 취급하지 않는다.
- 드래그 중에는 로컬 초안만 표시하고 놓을 때 cueRange 명령을 한 번 실행한다. 범위 밖·0 길이·겹침은 거부하고 원래 편집 상태를 유지한다.
- Ctrl/Cmd+C는 선택 자막을 앱 내부에 복사한다. Ctrl/Cmd+V는 재생 위치에 같은 길이·내용·스타일을 가진 새 ID의 자막을 붙인다. OS 클립보드 권한을 요구하지 않으며 겹치거나 끝을 넘으면 기존 오류 알림으로 설명한다.
- 자막은 독립된 프로젝트 시간 블록이다. 영상 재배열·삭제에 따라 자동으로 이동·삭제하지 않으며 사용자가 직접 옮긴다.

### 영상·자막 동시 분할

split 명령은 영상 배열과 자막 배열을 함께 계산한다. 영상 경계에 이미 컷이 있어도 그 위치를 가로지르는 자막은 나눈다.

```ts
if (cue.startUs < timeUs && timeUs < cue.endUs) {
  return [
    { ...cue, endUs: timeUs },
    { ...cue, id: newId(), startUs: timeUs },
  ];
}
```

왼쪽 ID와 양쪽 내용·스타일을 보존한다. 경계에서 다시 분할해도 0 길이 자막을 만들지 않는다. 하나의 프로젝트 명령/이력으로 확정하므로 undo 한 번으로 영상·자막을 함께 복원한다. 원본 오디오는 기존 클립 in/out을 계속 공유한다.

### 숫자 단축키와 보호

| 키 | 동작 |
| --- | --- |
| 1 | 재생 위치에서 영상과 교차 자막 함께 분할 |
| 2 | 선택 자막 또는 영상 삭제 |

기존 S, Delete/Backspace, Space, 프레임 이동, undo/redo를 유지한다. 입력·textarea·select·contenteditable·IME 조합·대화상자에서는 편집 단축키를 실행하지 않는다. 숫자키의 수정키·반복 입력도 보호한다. 화면·툴팁·도움말에는 1·2 설명을 추가하지 않았다. 이 표는 작업 문서에만 존재한다.

### 재생 시작·중단·재시도

- 무음 프로젝트는 performance.now() 시계를 사용하고 오디오 장치나 음성 디코더를 기다리지 않는다.
- 소리가 있는 프로젝트는 Web Audio 시계를 유지한다. 소리를 버리는 자동 무음 폴백을 추가하지 않았다.
- resume은 최대 4초 기다리고 실제 running 상태를 확인한다. 시작 대기 중에도 기존 정지 버튼으로 취소할 수 있다.
- statechange 중단 또는 2초 동안 멈춘 오디오 시계를 감지해 정지하고 기존 오류 영역에 알린다. 닫히거나 멈춘 장치는 다음 재생에서 다시 준비할 수 있다.
- 첫 미리보기 프레임을 받은 뒤 재생 시계를 진행한다. 프레임 대기도 최대 10초로 제한하고 정지·시킹·프로젝트 변경 때 취소한다.
- 오래된 시작 실패는 token 확인으로 새 재생을 정지시키지 않는다. 시작 타이머·프레임 대기·예약 오디오·RAF를 정리한다.
- 변경 없는 숫자 입력 blur와 동일한 영상 트림은 이력을 만들지 않아 불필요한 재생 중단을 줄였다.

기존 UI 배치·텍스트·도움말은 유지했다. 선택 테두리와 핸들은 요청한 자막 조작에 필요한 표시만 기존 레인에 적용했다.

```sh

npm test
npm run build
# 별도 터미널에서 npm run dev 실행 후:
npm run test:v2

```

v2 검사는 필요한 빨강/파랑/무음 합성 영상을 직접 생성한다. 기본 개발 주소는 http://127.0.0.1:5173/이며 다른 포트는 TEST_URL로 지정한다. Windows는 설치된 Edge를 사용하며 다른 환경은 기존 BROWSER_CHANNEL 규칙을 따른다.

### 범위와 한계

- 사용자의 원본 영상과 실제 장치 상태는 제공되지 않았다. 정상 합성 영상의 기존 재생 성공과 재현한 오디오/시작 문제를 구분했다. 모든 파일·기기에서의 재생 보장은 하지 않는다.
- 실제 OS 한글 IME의 모든 조합이나 모바일 제스처를 검사한 결과는 아니다. 기존 IME 보호 코드는 유지했다.
- 자막은 겹침 없는 단일 레인이다. 중첩 자막 합성, OS 클립보드 연동, 영상 이동에 자막을 자동 연결하는 기능은 추가하지 않았다.
- 변경은 로컬 코드와 문서에 반영했다. commit/push/공개 재배포는 수행하지 않았다. 원본 CHECKLIST.md와 해시는 유지한다.
