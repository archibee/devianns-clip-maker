# 녹화 업그레이드 V1

## 요구사항·구현

- [v] 미디어 패널에 아이콘이 있는 녹화 버튼을 추가한다. 브라우저가 제공하는 공유창에서 사용자가 다른 탭·창·화면을 직접 선택한다.
- [v] 공유 화면 미리보기와 소리 포함 여부를 확인한 다음 녹화를 시작한다. 소리가 공유되지 않았으면 무음 녹화임을 화면에 표시한다. 미리보기 소리는 끄되 녹화의 공유 오디오는 보존한다.
- [v] 녹화 완료 시 최종 데이터 수신·파일 생성 이후 기존 임포트 경로로 영상 에셋을 즉시 추가한다. 타임라인에 자동 배치하지 않으며 사용자가 기존 추가·드래그 방식으로 사용한다.
- [v] 브라우저에서 공유를 중지해도 진행 중 녹화를 완료한다. 취소는 결과를 추가하지 않고 모든 공유 트랙·인코더·임시 청크를 해제한다. 선택창 응답이 늦게 도착해도 취소된 스트림을 즉시 중지한다.
- [v] 녹화 로직은 `modules/screen-recorder`에 분리하고 UI에서 코덱을 직접 다루지 않는다. 프로젝트에는 원본 File이나 스트림을 직렬화하지 않는다.
- [v] 녹화 청크는 128MiB 상한으로 관리하며 한도에 가까워지거나 30분에 도달하면 완료한다. 한 번의 청크가 상한을 넘는 예외는 오류로 처리하고 손상된 결과를 자동 추가하지 않는다. 이 제한은 일반 영상 내보내기의 제한과 별개다.
- [v] 지원하는 WebM 또는 MP4 형식을 선택하고 실제 MIME에 맞는 확장자를 사용한다. 임포트 실패 시 기존 프로젝트를 유지하며 녹화 파일을 별도로 저장할 수 있게 한다.
- [v] HTTPS/localhost 및 API 지원 여부를 확인하고 지원하지 않는 브라우저에는 이유를 안내한다. 녹화·원본·프로젝트를 서버로 전송하지 않는다.

## 지원 범위와 사용

다른 탭 녹화는 `getDisplayMedia`와 `MediaRecorder`로 구현한다. 공유 대상은 앱이 강제로 고르거나 권한을 재사용하지 못하며 매번 사용자가 선택한다. 탭 소리를 포함하려면 브라우저 공유창의 소리 공유를 켜야 한다. 모바일·태블릿의 화면 캡처 지원은 브라우저에 따라 다르며 미지원 환경에서 우회 캡처를 제공하지 않는다. [화면 캡처 API](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia), [Chrome 녹화 안내](https://developer.chrome.com/docs/extensions/how-to/web-platform/screen-capture)

녹화 버튼 → 녹화할 탭 선택 → 화면·소리 확인 → 녹화 시작 → 녹화 완료·에셋에 추가 순으로 사용한다. 녹화 결과는 영상 에셋이며 정지 이미지 생성 기능은 포함하지 않는다. 프로젝트 JSON은 원본 영상을 포함하지 않으므로 ‘녹화 파일 저장’으로 원본도 보관해야 다른 세션에서 다시 연결할 수 있다.

## 확인 결과

Windows headless Edge 157.0.4341.60에서 별도 탭의 합성 화면·소리를 실제 화면 공유 API로 녹화했다. 생성 WebM의 영상·Opus 소리를 디코딩하고, 자동 에셋 추가·타임라인 삽입·재생 및 480p/30fps MP4 출력의 영상·AAC 소리까지 확인했다. 취소 후 에셋 미추가도 확인했다. 브라우저 공유 선택만 자동화 옵션으로 승인했으며 캡처 API나 MediaRecorder는 모킹하지 않았다.

`scripts/record-browser-test.mjs`로 재현하며 결과는 Git 제외 경로 `test-results/record-v1/`에 기록한다. 실제 모바일 화면 공유·Safari·장시간 녹화는 미검증이다. 단위 검사에서는 선택 지연 후 취소, 일반 완료, 녹화 폐기, 공유 중지, 버퍼 상한을 확인한다.

`npm test`의 77개 검사와 `npm run build`가 통과했다. 화면 공유 API가 없는 환경의 안내 및 선택 버튼 비활성화도 브라우저 검사에 포함했다.
