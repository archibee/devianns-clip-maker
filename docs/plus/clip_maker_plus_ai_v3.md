# Devianns Clip Maker Plus · AI V3

## 두 계층으로 분리

AI 기능을 **AI Gen 모듈**과 **AI API 연결 모듈**로 분리한다. V2의 단일 AI 자막 모듈 구상은 아래 구조로 구체화한다.

`기존 편집기 → AI Gen 모듈 → AI API 연결 모듈 → 공급자별 API`

| 계층 | 책임 | 포함하지 않는 책임 |
| --- | --- | --- |
| AI Gen | 클립메이커의 자동 자막 생성 기능, 모달, 작업 진행·취소, 음성 구간과 전사 결과 연결, 결과 편집, 완료 시 적용 | 공급자 인증·URL·요청 형식·응답 형식의 직접 처리 |
| AI API 연결 | 공통 호출 인터페이스, 백엔드 엔드포인트, 인증, 공급자 선택, 기능 지원 확인, 요청·응답 변환, 타임아웃·취소·오류 정규화 | 타임라인 수정, 자막 블록 생성, 편집기 UI·프로젝트 상태 관리 |

## AI Gen 모듈

- 자동 자막 생성 기능의 이름을 **AI Gen**으로 정한다. 버튼·모달도 이 명칭을 기준으로 구성한다.
- 기존 프로그램과 분리된 추가 기능 계층으로 구현한다. 프로젝트 스냅샷을 입력받아 음성 분석·전사 요청·자막 초안을 자체 임시 상태에서 처리한다.
- AI API 연결 모듈의 공통 인터페이스로 음성인식을 요청한다. 공급자가 DeepSeek인지 다른 API인지에 따라 AI Gen 내부 흐름을 직접 분기하지 않는다.
- 완료 시에만 검증된 결과를 기존 편집기의 적용 인터페이스로 전달한다. 취소·부분 실패·오래된 응답은 프로젝트를 변경하지 않는다.
- 기존 영상·자막은 보존하고 새 라인에 자막을 일괄 추가하며 실행 취소를 지원한다. AI Gen의 실패가 Auto Cut·Auto Caption·기본 편집 기능에 전파되지 않도록 오류 경계를 둔다.

## AI API 연결 모듈

- 자막 생성에 종속되지 않는 공용 계층이다. 이후 다른 AI 기능도 이 모듈을 호출할 수 있다.
- 프런트엔드용 클라이언트와 서버용 호출 처리를 분리한다. 공급자 키와 실제 공급자 호출은 서버에서만 처리한다.
- 초기 공급자는 DeepSeek로 하되 공급자별 어댑터를 등록하는 방식으로 다른 AI를 추가할 수 있게 한다. 키나 URL만 바꾸면 모든 API가 호환된다고 가정하지 않는다.
- 음성인식·텍스트 생성 등 지원 작업을 구분하고 공통 계약을 정의한다. 예를 들어 음성인식은 음성 데이터와 요청 ID를 받아 텍스트 및 제공 가능한 시간 정보를 반환하고, 텍스트 생성은 별도 입력·출력 계약을 사용한다.
- 공급자별 모델·인증 방식·엔드포인트·요청 형식·응답 형식은 어댑터가 처리한다. 지원하지 않는 작업은 호출 전에 명확히 거절하며 다른 공급자로 임의 전송하지 않는다.
- 응답은 공통 형식으로 정규화하되 공급자가 제공하지 않는 타임스탬프를 만들어 내지 않는다. 음성 구간의 프로젝트 시간 매핑은 AI Gen의 책임이다.
- 요청 ID, 취소 신호, 타임아웃, 정규화된 오류 계약을 제공한다. 과금 요청의 무조건적인 자동 재시도는 피한다.
- 공급자 및 기본 URL은 서버의 허용된 설정으로 관리한다. 클라이언트가 임의 URL이나 서버 키를 지정해 요청을 우회하지 못하도록 한다.
- 표준 HTTP 인터페이스와 플랫폼 독립적인 서버 핵심 로직을 사용한다. Vercel·다른 서버리스·일반 서버는 배포 진입 어댑터로 연결한다.

## 경계와 적용 흐름

1. 기존 편집기에서 AI Gen 모달을 연다.
2. AI Gen이 대상 라인 스냅샷을 기준으로 음성 구간과 요청 데이터를 준비한다.
3. 공용 AI API 연결 모듈이 서버를 통해 선택된 공급자에 요청한다.
4. AI Gen이 정규화된 결과를 시간 구간에 연결하고 사용자에게 자막 초안을 보여 준다.
5. 사용자가 완료하면 프로젝트 변경 여부와 결과를 검증한 뒤 한 번에 적용한다. 완료 전에는 기존 프로젝트를 수정하지 않는다.

이번 V3는 명칭·계층·책임을 정리하는 설계 문서이며 코드 구현이나 API 호출은 수행하지 않는다. V2의 전사 방식·외부 전송 안내·서버 키 보호·실패 시 미적용 원칙은 유지한다.
